# DIS — NMT Discovery Adapter v0.1
**Роль:** маршрутизатор между DIS Discovery и публичными skills Next Move Theory / Advanced Jobs To Be Done Ивана Замесина.  
**Статус:** CANDIDATE — спецификация интеграции; **не является установленным skill**.  
**Зафиксированная ревизия внешнего источника:** \`f8e87d10255b48d381ebc7fa65172960eb6d483f\`.  
**Источник:** https://github.com/zamesin/Next-Move-Theory-Canon-and-Skills

## 1. Принцип
NMT — специализированная методика понимания Jobs, рынков и продуктовых решений. DIS — **управляющая методология этапов**. Включение NMT не отменяет DBR-001, RQC-001, Source Register, Stage Cycle, авторский checkpoint, потребность в реальных источниках или проверку итогового дизайн-результата.

**Нельзя включать весь NMT pipeline для любого сайта.** При старте Discovery DIS выбирает соответствующий skill по задачам и доступным данным, показывает выбор оператору и проверяет, что skill **фактически подключён**, а не просто упомянут в промпте.

## 2. Маршрутизация
| Контекст задачи | NMT skill | Когда не нужен |
|---|---|---|
| Новая идея, выбор рынка / сегмента / Jobs | \`nmt-market-research\` | Бизнес и продукт известны, не стоит задача выбирать рынок |
| Уже работающий продукт, проблема метрик/роста | \`nmt-diagnose\` | Нет реальных метрик и проблемы действующего продукта |
| Есть реальные интервью, заметки, звонки | \`nmt-analyze-interviews\` | Нет реальных записей: запрещено выдумывать интервью |
| Нужна навигация по NMT или прояснение гипотез | \`nmt-chat\` | Уже известен специфический producer-skill и его входы |
| Требуется формирование ценности для выбранных Jobs | \`nmt-craft-value-proposition\` (по ситуации) | Нет согласованного сегмента/Jobs/ценности |
| Требуется PRD по продукту, а не только концепт страницы | \`nmt-product-requirements\` (по ситуации) | Scope только визуальная концепция, PRD не нужен |
| Нужны GTM/landing copy на основе NMT | \`nmt-craft-go-to-market\` (по ситуации) | Не предусмотрено в Research/Delivery Scope |

## 3. Вызов и границы
1. На вход передаются конкретные доступные источники проекта, исследовательская задача и разрешённая глубина (Quick/Deep), статус данных (факт/заявление/гипотеза).
2. Прежде чем запускать NMT, учитывать статус лицензии, права, действительное наличие skills в текущем Codex checkout и права на данные. Тексты/шаблоны NMT нельзя вендорить в DIS без прав.
3. NMT результаты сопоставляются с требованиями DIS; теоретические Job/рынок без полевых подтверждений — **гипотезы**. Не подменять «GO (to validation)» решением «строим продукт».
4. Результат дискавери передаёт не весь сырой отчёт в визуальный промпт, а traceable **вывод → доказательство/гипотеза → влияние на продукт/контент/UX → критерий проверки**.
5. При недоступности skills: статус \`NMT_NOT_CONNECTED\`/ \`RIGHTS_REVIEW_REQUIRED\`, без ложного PASS. DIS может продолжить обычный Discovery по DBR-001, если это согласовано оператором и допустимо по Scope.

## 5. Acceptance tests
- Новая идея → рекомендуется Market Research, без фальшивых интервью.
- Действующий продукт → Diagnose, с оговоркой о доступности метрик.
- Интервью есть → Analyze Interviews, с source-to-claim trace.
- Данные отсутствуют → обозначен validation debt, источники не сфабрикованы.
- Skill не установлен → NO CLAIM OF EXECUTION.
- Пользователь выбрал Express → NMT Deep не запускается автоматически.
- Отчёт сформирован → этап **не утверждается** без отдельного author action и GitHub фиксации.
- Изменился upstream evidence → связанные утверждения помечаются для проверки.
