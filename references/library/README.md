# DIS — Reference & Calibration Library

**Статус:** живая библиотека · с 25.10.2026. Не путать наличие карточки с художественным утверждением.  
**Владелец процесса:** DIS в активных Research, Art Direction и ретроспективах; существенные художественные утверждения — арт-директор.  
**Метод:** [Reference Evidence & Calibration](../../methodology/reference-evidence-calibration.md) · [Studio Signature](../../methodology/studio-signature-evolution.md).

## Один индекс — разные роли записей

- `trend_signal` — ежегодный/редакционный тренд или прогноз, **не рейтинг качества**.
- `reference_candidate` — перспективный внешний пример, ещё не изученный детально.
- `analysed_reference` — изученный проект с применимыми приёмами, сильными и слабыми сторонами.
- `calibration_benchmark` — тщательно проверенный пример качества **в явно указанных осях**, не «универсальный 9/10».
- `our_accepted_work` — собственное принятое человеком решение, только в согласованном объёме.
- `anti_example` — источник выявленного дефекта с обоснованием и границами применимости.
- `studio_pattern` — запись собственного авторского приёма, со статусом от гипотезы до утверждённого.

Типы можно совмещать; запись обязательно указывает фактический уровень свидетельств. Для ключевых внешних примеров — источник/автор/дата, скрин или URL просмотренного экрана, оценка платформы (только если проверена), семантическая применимость и явно **что не переносим**.

## Обязательное событийное накопление и зрелость

[Reference Engine Protocol](../../methodology/reference-engine-protocol.md) и [Reference Memory skill](../../skills/reference-memory/skill.md) задают обязательные исследовательские события от обнаружения до применения/отзыва, отсутствие лазейки «по возможности», идемпотентность, provenance, статусы сбоя. **Сейчас это операционная спецификация; программный сборщик ещё не интегрирован.** До этого в активном проекте нужен честно обозначенный ручной checkpoint, не фиктивная автоматика.

С первого источника включаются накопление и точечный recall. Экспериментальный Maturity Gate для расширенного внутреннего поиска: ≥150 действительно просмотренных уникальных refs, ≥8 отраслей, ≥20 различимых механизмов, ≥15 глубоких разборов и ≥4 успешных теста из 5. Ранний REUSE уже утверждённого решения не запрещён. Для новой художественной задачи независимый внешний поиск обязателен даже в зрелой библиотеке.
## Как растёт

Текущий проект → исследование → запись/обновление по реальному evidence → применение → ревью → при достаточной доказательности повышение роли → на checkpoint синхронизация с GitHub.

Не сохранять десятки почти идентичных ссылок без пользы; карточку объединять по назначению приёма, оставляя происхождение. Не придумывать дату награды, рейтинг, проверенное поведение, авторство или человеческий художественный балл. Для защищённых изображений хранить ссылки/метаданные, не копировать чужие полноразмерные материалы без прав.

Без активной задачи нет фонового пополнения. Обновление ежегодных гайдов — при новом проекте/пересмотре визуального направления, не фиксированным ежедневным cron.
