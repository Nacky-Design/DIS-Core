# Перед передачей репозитория новичку

- Проверьте, что GitHub Actions `DIS Core integrity` показывает PASS после загрузки.
- Откройте `README.md`, [инструкцию для новичка](docs/dis-operator-guide-v2-alpha.md) и [стартовый промпт](prompts/dis-project-bootstrap-v2.md) прямо в GitHub и убедитесь, что все три доступны без авторизации.
- Отправьте новичку **ссылку на этот репозиторий** и ссылку на инструкцию. Задача/бриф передаются отдельно, без конфиденциальных материалов в публичном репозитории.
- Попросите создать собственный **private** репозиторий проекта. Не отправляйте токены в чат.
- Не подсказывайте шаги до первой остановки: нам важно увидеть, какие инструкции он понял самостоятельно.
- Фиксируйте проблемы с указанием шага, экрана/сообщения, ожидаемого и фактического результата. Статусы `NOT_CONNECTED`, `NOT_VERIFIED` и `PROCEDURAL_ONLY` — не ошибки новичка.
- Альфа-режим **не реализует защищённое SRA/SSA** без отдельного сервиса подтверждения. Нельзя считать процедурную запись технически утверждённым этапом.

**По желанию:** предложите новичку [Pilot Monitor v0.1](docs/pilot-monitor-v0.1.md) — приватный журнал маршрута, ошибок и решений. Он выключен без отдельного согласия, не перехватывает чат и требует подтверждённого доступа на запись в проектный GitHub. Не создавайте журнал в публичном DIS-Core; приватный репозиторий должен оставаться под контролем новичка.

Полный сценарий: [протокол тестирования](tests/novice-pilot-protocol-v1.md).
