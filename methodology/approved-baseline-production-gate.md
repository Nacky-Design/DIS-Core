# DIS — Approved Baseline Production Gate (ABPG-001)

**Дата:** 03.11.2026. **Статус:** обязательный процедурный контроль, **не физическая блокировка** внешних image-generation tools. Связан с [Stage Transition Guard](stage-transition-guard.md), [Visual Quality Gate](visual-quality-gate.md), [Whole-Page Continuity](full-landing-continuity.md) и [Concept Integrity](concept-integrity.md). Вводится после повторяющихся отклонений в anonymized internal pilot MedLanding A2/A5.

## Проблема, выявленная в пилоте
Зафиксированные решения (решения в GitHub, LOCKED-тексты, референсы, UI Kit) **не были подхвачены как защищённые исходные артефакты в момент генерации**. Для A2 при запросе поменять только левое фото перерисовывались правые тексты, иконки и сетка; неоднократно утверждалась «пиксельная идентичность» без достоверного pixel diff. Для A5 «anonymized internal pilot», где нужно воспроизвести композиционную архитектуру принятого кейса РНЦХ и заменить контент, генератор построил новый сиреневый рекламный hero двух телефонов, потеряв показатели, чипсы и инженерный смысл. Ошибка — не отсутствие формулировки «соблюдать», а **отсутствие проверяемой цепочки evidence → разрешённый scope → output comparison → delivery**.

## Два режима — не смешивать
- **MODE A: LOCAL_PATCH.** Меняется строго обозначенная область существующего **человеком утверждённого** файла. Если LOCKED требуется в буквальном смысле, используется маска, исходные пиксели/слои и композитинг, **не полная перегенерация**. Внешний image model не считается инструментом гарантированной пиксельной сохранности.
- **MODE B: APPROVED_PATTERN_TRANSFER.** Новый блок того же семейства на основе утверждённого образца (РНЦХ → anonymized internal pilot). Сохраняется **система**: сетка, редакционные оси, иерархия типографики, типы полей/метрик/чипсов, цвет, расположение visual/story; собственный текст, реальные значения и новая предметная сцена меняются согласно контракту. Внешнее сходство без структурных полей = FAIL. Здесь pixel-identical **не** требуется, потому что контент различается.
- **MODE C: NEW_CONCEPT.** Только когда пользователь явно запросил новую композицию или нет утверждённого образца. Тогда полная цепочка STG-001; нельзя выдавать MODE C за A или B.

## Preflight — обязательно до вызова инструмента
1. Назвать project/section, mode, target artifact (PNG/Figma/HTML), источник контента и **точную** версию утверждённого baseline (доступный файл/скриншот, path/hash или user-visible reference). **Файл решения в GitHub не заменяет изображение.**
2. Доказать, что baseline *действительно доступен* и конкретные решения *утверждены пользователем*. Если недоступен — `STOP_MISSING_BASELINE`; запросить исходник либо выполнить только незатрагивающую LOCKED подготовку. Запрещено импровизировать «по памяти».
3. Выписать `LOCKED | EDITABLE | DEPENDENT` по компонентам; для MODE B дополнительно перечислить неизменные **типы структурных элементов** и заменяемый клиентский контент.
4. Выбрать технологию **по требуемой точности**: image generation для нового художественного содержимого, точный композитинг/маска для LOCKED-пикселей, настоящий текст/слои для типографики; не просить генератор сделать невозможную детерминированную замену.
5. Вписать проверяемые **acceptance criteria**, например A5: kicker/клиент, H2, lead, 4 показателя, directions/chips и правый hero visual; фальшивые функции, цифры или логотип = FAIL.

## Pre-delivery gate — до показа как концепции
- **Structural diff**: наличие всех обязательных полей и правильная семантическая группировка; сравнение композиции с baseline.
- **Content check**: утверждённые тексты и числа из брифа, отличить реальные данные от временных; не выдумывать claims, показатели, устройства и функции.
- **Visual fidelity**: сетка/оси, типографические роли, масштаб, радиусы, плотность, фон, фото/интерфейс. Проверять **реальное** изображение, не только промпт.
- **Patch integrity** (MODE A): исходные LOCKED-пиксели/слои должны быть перенесены из исходника. Если возможен пиксельный diff — сравнить незатронутые области; проверить маску, seam, края и crop. При отсутствии проверяемого сравнения писать `not_verified`, не «pixel perfect».
- **Product fidelity**: реалистичная геометрия устройств, осмысленная связь экранов, роли субъектов, дата/время/статус, читаемые подписи; не подменять смысл высокими художественными оценками.

Провал любого критического пункта => `STOP_BASELINE_REGRESSION`, **не предъявлять как готовый/утверждаемый результат**. Разрешена краткая явная демонстрация дефекта только по просьбе пользователя как `exploratory_not_ready`. Две повторные однотипные регрессии => `STOP_METHOD_FAILURE`: сменить метод (композитинг, Figma/кодовые слои, другой визуальный носитель) или перейти к следующему согласованному блоку. Не выпускать третью вариацию той же ошибки без изменения способа.

## Реализация и честный статус
- **Сейчас:** L0 — исполняемая агентом инструкция/checklist и ручная проверка. Это **не автоматический блокировщик** image_gen в ChatGPT.
- **Для L1:** создать manifest contract + валидатор обязательных полей, source refs, statuses и image/DOM diff в доступном рабочем репозитории; запускать как обязательный preflight/pre-delivery command. Такой валидатор способен проверить геометрию и данные, но **не художественную ценность без экспертного ревью**.
- **Для L2:** ограничить прямые production calls за permissioned gateway и подключить required checks к рабочему клиентскому репозиторию; без этого нельзя говорить «технически невозможно нарушить».
- Репозиторий DIS документирует контракт, но сам по себе не подключает CI/permissions к браузерному Codex, ChatGPT и Figma. Каждый конкретный клиентский проект обязан проверить локальную установку и подключение.

## Текущее проектное решение
A2: утверждён только конкретный desktop popup «Интеграции и данные» (см. решение (private evidence not included)); прочие popup и новая галерея не утверждены. Для A5 утверждён **образец композиции РНЦХ**, но PNG A5 «anonymized internal pilot» не утверждалась. Пилотный маршрут PNG → Figma → Codex сохраняется. Цель — собрать целую страницу, не застревая в неудачных повторных генерациях.
