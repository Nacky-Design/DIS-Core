# DIS Pilot Monitor v0.1 — наблюдение за альфа-тестированием
**Статус:** инструмент подготовлен для проверки, но не подключён к чужому ChatGPT автоматически.

Назначение: видеть **маршрут новичка**, **обнаруженные проблемы** и **попытки их решения** без чтения его переписки и записи экрана.

## Что фиксируем
- `route_selected` — выбранный маршрут;
- `stage_entered`, `stage_exit_requested`, `stage_blocked` — движение по этапам;
- `error_detected` — обнаруженная проблема, её короткий ID `ERR-001`;
- `fix_attempted` — что пробовали изменить;
- `fix_result` — результат попытки: `PASS_REPORTED`, `FAIL_REPORTED` или `NOT_CHECKED`;
- `monitor_stopped` — прекращение регистрации событий.

**Не собираем:** полный текст запросов/ответов ChatGPT, изображения экрана, клавиши, пароли, токены, личные данные, клиентские материалы и содержимое исходников. Описания событий короткие (до 240 символов); ссылки, email и очевидные секреты автоматически отклоняются. Не используйте настоящие имена в описаниях.

## Как подключить к тесту
1. Новичок получает инструкцию DIS Core, создаёт **собственный PRIVATE GitHub-репозиторий** для проекта.
2. Отдельно от общих условий ChatGPT он **соглашается или не соглашается** на ведение минимального технического журнала. По умолчанию наблюдение выключено.
3. Если согласен, ответственный за пилот или подключённый контроллер создаёт в **приватном проекте**, а не в публичном DIS Core, файл `.dis/pilot-monitor.json`. Файл создаётся только через `initialize_remote_monitor(..., consent=True)` или эквивалентный защищённый интерфейс.
4. При известных событиях подключённый DIS/Codex передаёт их в `append_remote_event`. За каждую запись GitHub должен вернуть commit и подтвердить readback. Никакого автоматического доступа к сообщениям ChatGPT этот инструмент не имеет.
5. Исследователь пилота может читать журнал **только если новичок явно дал ему GitHub-доступ** к приватному репозиторию. Не просите делать проект публичным.
6. В любой момент новичок может остановить регистрацию, записав `monitor_stopped`, или отозвать доступ наблюдателя. Прекращение доступа не стирает предыдущие Git-коммиты; удаление прошлых событий требует отдельного согласования политики хранения и Git-истории.

## Что означает подтверждение
`MONITOR_EVENT_SAVED` подтверждает **GitHub-запись**, а не объективную правдивость записи модели. `agent_reported` означает «сообщила модель», `operator_reported` — «со слов оператора», `controller_observed` — «зарегистрировал подключённый контроллер»; эти значения не являются цифровой подписью. Результат `PASS_REPORTED` остаётся **заявлением об исправлении**, пока не проверены реальный файл, источник или поведение.

Ни один мониторинг не превращает процедурное решение в подписанный SRA/SSA и не включает скрытый перехват браузера.

## Отчёт
Внутренний инструмент `tools/enforcement/pilot_monitor.py` умеет строить краткое резюме: выбранный маршрут, историю этапов, ошибки с ID, попытки исправления и последний *заявленный* исход. Он не считает личность, время за компьютером или количество нажатий.

При отсутствии доступа на запись в проектный GitHub монитор честно сообщает `NOT_CONNECTED`. Можно продолжать альфа-пилот **без мониторинга**, не обещая скрытую регистрацию.

**Для организатора:** основной журнал всегда в приватном проекте новичка. Публичный `Nacky-Design/DIS-Core` содержит только код, эту инструкцию и синтетические тесты.
