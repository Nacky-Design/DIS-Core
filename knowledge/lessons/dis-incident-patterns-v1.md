# DIS — Обезличенные уроки из пилотов · v1
**Основа:** внутренние аудиты исполнения и ретроспективы разных проектов DIS. Формулировки ниже обобщены, без источников, идентифицирующих клиента. Это *наблюдения и предложения проверки*, не независимые измерения эффективности.

## KB-01 · READ ≠ COMPLY
- **Наблюдавшийся класс ошибки:** агент перечисляет утверждённые правила, но реальный файл нарушает одно или несколько требований.
- **Потенциальный механизм:** утверждения прочитаны, но не преобразованы в исполнимый список требований и фактические проверки. Причинность не доказана.
- **Защита:** `DEC-001` с requirement IDs, version pin, source hash, критерием, ожидаемым изменением и реальным evidence.
- **Негативный тест:** файл не изменился при запросе на правку или содержит непроверенное значение — нельзя писать PASS.
- **Статус:** OBSERVED_IN_INTERNAL_REVIEW; наличие структурных тестов не означает независимый browser QA.

## KB-02 · Protected baseline / локальная правка
- **Наблюдавшийся класс ошибки:** локальная замена одного элемента приводит к перепроектированию другой, ранее принятой части интерфейса.
- **Защита:** явно фиксировать `must_change`, `must_preserve`, `may_change`, исходный baseline@SHA; сравнивать фактический результат, не обещать pixel-perfect без соответствующей проверки.
- **Негативный тест:** заявленная локальная правка изменила защищённую типографику, структуру или текст — NEEDS_WORK.
- **Статус:** OBSERVED_IN_INTERNAL_REVIEW; художественная сохранность требует экспертного суждения.

## KB-03 · Полнота решений до утверждения
- **Наблюдавшийся класс ошибки:** клиенту показывают концепцию с бесхозными CTA, неподтверждённым контентом, неверными или дублированными медиа.
- **Защита:** перед выбором зафиксировать user/job, действие CTA, destination/state/back path, происхождение assets и факты против гипотез. Спорные функции допускаются в прототип только с явной пометкой.
- **Негативный тест:** CTA не ведёт к определённому результату либо обозначен рабочим, хотя это mock.
- **Статус:** OBSERVED_IN_INTERNAL_REVIEW; эффект снижения итераций EXPERIMENTAL.

## KB-04 · Preview ≠ Delivery
- **Наблюдавшийся класс ошибки:** пользователь видел одну хорошую версию, а получил другую в ZIP/HTML/презентации; портативный HTML-превью может содержать только PNG и не быть интерактивным прототипом.
- **Защита:** выпуск только из проверенной версии, SHA/manifest реальных файлов, маркировка `static-preview` / `interactive-prototype`, проверка ссылок, ролей элементов и openability.
- **Негативный тест:** нет точного файла, CRC архива неверен, preview не совпадает с release или интерактивность ложно обещана — FAIL.
- **Статус:** OBSERVED_IN_INTERNAL_REVIEW; структурные архивные проверки технически воспроизводимы.

## KB-05 · Stage Gate / Approval integrity
- **Наблюдавшийся класс ошибки:** цель «получить HERO» ошибочно интерпретируется как разрешение сразу генерировать визуал до Discovery/Art Direction/UI Kit.
- **Защита:** Stage Start Packet, заранее заданные Acceptance Criteria, exit check, отдельный подписанный операторский SRA и следующий SSA, если доверенный сервис реально подключён.
- **Негативный тест:** попытка вызвать производственный инструмент при пустом upstream или поддельном статусе утверждения — STOP.
- **Статус:** OBSERVED_IN_INTERNAL_REVIEW; контроллер покрывает только маршрутизируемые вызовы, **native-tool interception не подтвержден**.

## KB-06 · Технический PASS ≠ художественная приемка
- **Наблюдавшийся класс ошибки:** отсутствие overflow или автоматическая эстетическая оценка не выявляют слабую иерархию, кадрирование, текстовый ритм и несоответствие UI Kit.
- **Защита:** технический browser/style QA по точной версии отдельно от авторского Visual Review; тестировать применимые реальные размеры, состояния и смысл.
- **Негативный тест:** красивые self-score и успешный lint при несоответствии утверждённому визуальному базису не дают `approved_by_user`.
- **Статус:** OBSERVED_IN_INTERNAL_REVIEW; количественная полезность полного контроля EXPERIMENTAL.

**Публичная оговорка:** примеры синтетические, не воспроизводят оригинальные визуалы, названия, сроки и уникальные исходные данные клиентов. Для настоящего подтверждения использовать приватные источники с разрешённым доступом.
