# DIS PCS-001 — Reference Intelligence · Universal Stage Prompt v1.1
**Stage:** `reference_intelligence` · **Status:** stage-specific universal prompt, not permission to start.

Use the exact approved Stage Start Snapshot, prior approved Discovery, Semantic Architecture, Prototype (when applicable), original client materials and explicit current Design Scope. Read the actual `.agents/skills/dis-reference-intelligence/SKILL.md` and applicable [Reference Engine](../methodology/reference-engine-protocol.md), [Evidence Calibration](../methodology/reference-evidence-calibration.md) and [Skill Standard](../methodology/skill-execution-standard.md). If an expected source is unavailable, mark `NOT_VERIFIED`; do not substitute the separate **competitive research** stage.

**Goal:** build a sourced, transferable visual reference selection for the proposed concept—not generic competitor market analysis.

**Process:**
1. Define the exact visual/UX question and already LOCKED constraints; list optional investigations (motion, typography, composition, navigation, photography) agreed before this stage.
2. Choose **operator references / independent external search / combined**. Actually open and inspect the referenced sources; distinguish `discovered` from `visually_reviewed` and `interaction_verified`.
3. Identify the source mechanism: what performs which function, what the operator values, and what is transferable to this project's problem without copying design or brand.
4. Present materially different, credible alternatives. Record the operator's selected, rejected and still-hypothetical directions with source URLs, dates, observations, limitations and use rights.
5. Write one current Reference Intelligence artifact and decision ledger in the project repo; include a specific Art Direction handoff, not merely a moodboard.
6. Apply **DEC-001** to every applicable approved source, requirement and protected detail. Before production require `DEC_PRE_EXEC_PASS`; after production inspect the actual artifact and only then offer Stage Exit/SRA-001.
7. **Stage Exit Check:** source ledger exists; selected and rejected references are traceable; copied vs adapted mechanisms are explicit; required subtopics have been inspected (or blocked with honest evidence); material contradictions and unvalidated assumptions are visible. No arbitrary minimum number of references.
8. Do not auto-approve, auto-promote or launch Art Direction after a user merely says «Переходим к следующему этапу». Produce the structured exit summary, offer **Углубить / Доработать / Утвердить этап**, and await explicit SRA for the exact version. A verified GitHub commit and a separate SSA are required for next-stage production.

**Status warning:** the source skill's specification is not proof that a particular Codex workspace installed its automation, external collector or browser inspection.
