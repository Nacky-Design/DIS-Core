# DIS PCS — Universal Stage Result Prompt v1.1
Template ID PCS-RESULT-1, schema PCS-001/v1.

Load the exact approved Stage Start Snapshot and verify unchanged input identities. Review actual artifact against every applicable LOCKED and GUIDED inherited decision (including non-adjacent stages), original company baseline, UI Kit status, selected artistic mechanisms, source citations and all promised outputs. Perform applicable factual/structural/visual/mobile QA and report evidence or NOT_CHECKED. Submit one current human-readable stage document and its attachments as PROPOSED. Await explicit separate user exit approval for this exact version and scope. Reject status propagation from unapproved or failed work. Only after exit approval pin the version and open the next stage. No self-certification.

## Human result decision options (DBR-001 / all DIS stages)

After actual output QA, present both **Approve this exact stage result (SRA-001)** and **Conduct substantive critical review / propose author edits**. Critical review must inspect underlying sources, traceable evidence, contradictions and possible ungrounded claims; do not simply compliment or repeat a green structural gate. Author's natural-language explicit approval is a valid *recorded conversational decision* for the exact scope; it is **not** a cryptographically verified issuer receipt. Explicit revision requests keep status NEEDS_WORK and preserve stage context. Never treat approval of a result as an SSA for the next stage. Create next proposed Stage Start Packet only and await separate SSA.

## Required DEC-001 result contract
**Ни один этап DIS не имеет права начинать производство на основании простого ознакомления с документами. Каждое применимое утверждённое требование должно быть перенесено в исполнительный контракт, а его выполнение — проверено на фактическом результате.**

Use the *same* DEC-001 ledger requirement IDs used before production to audit the actual final artifact. Provide observed artifact evidence, `PASS | FAIL | NOT_CHECKED` for every active requirement. No evidence means `NOT_CHECKED`, not `PASS`. Critical FAIL or NOT_CHECKED => REJECTED and no promotion. Only after actual-artifact QA may SRA-001 be requested; independent author approval is still separate.
