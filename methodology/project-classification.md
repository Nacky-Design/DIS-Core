# DIS — Project Classification & Process Depth · v0.1

**Дата:** 22.10.2026. **Статус:** рабочая методологическая схема для следующих пилотов; типовые рекомендации и пороги не доказаны экспериментально.

## Фундаментальная идея

DIS применяет **одни и те же принципы** к сайтам-визиткам, лендингам, промосайтам, корпоративным сайтам, каталогам, e-commerce, веб-сервисам и другим цифровым продуктам. **Тип проекта — контекст, не команда выбирать конкретный дизайн, объём исследования или инструмент.** Глубину процесса определяют реальные сценарии, информационная архитектура, число уникальных шаблонов/состояний, риски, контракт и неопределённость.

Отделяй четыре оси:
1. **Тип продукта:** визитка / лендинг / промо / корпоративный / каталог / e-commerce / сервис / смешанный и иной.
2. **Структурная сложность:** одна область/экран; несколько секций одного сценария; разные типы страниц; много сценариев, ролей, состояний, интеграций.
3. **Неопределённость:** зрелость исходников и бренда, ясность позиционирования, объём неподтверждённого контента, наличие проверенных маршрутов.
4. **Производство и риски:** бюджет, результат по договору, CMS/данные, визуальная оригинальность, motion, взаимодействия, будущая поддержка.

Не своди их в один магический «балл сложности» и не выводи глубину работы из названия типа сайта.

## Режимы глубины, не рейтинги качества

| Режим | Признак задачи | Достаточное проектирование | Контрольная точка |
| --- | --- | --- | --- |
| **Focused** | Одно локальное изменение / hero / ясный небольшой экран | Проверить затронутый смысл, окружение, функцию, mobile и существующий источник истины | Краткая content-first схема / явно принятая структура, если она уже есть |
| **Page/System Lite** | Много секций, один или несколько основных маршрутов | Полная смысловая схема страницы, связи секций, CTA, адаптивная логика; достаточный прототип | Согласованная структура и сценарий **всей страницы** до художественного производства |
| **Multi-template** | Несколько уникальных типов страниц, каталог, корпоративный сайт | Sitemap/IA + карта шаблонов + ключевые пользовательские маршруты + основные состояния и примеры страниц | Согласованная система страниц/шаблонов и репрезентативные прототипы |
| **Product/Transactional** | Покупка, кабинет, сложные формы, роли, сравнения, сценарии с состояниями | Задачи/потоки + IA + функциональные прототипы критичных путей и состояний, требования к данным и ошибкам | Согласованы критические маршруты и сценарии до разработки зависимых частей |

Режим выбирают **по содержанию**, не по ярлыку продукта. E-commerce может быть простым небольшим каталогом; промосайт — технологически и интерактивно сложным. Смешанному проекту назначать общую рамку и специальные проверки только для сложных маршрутов. Режим можно изменить с объяснением; не перезапускать завершённые этапы автоматически.

## Общий процесс DIS для всех типов

`Intake / Research → Prototype checkpoint → Production Route Selection → Art Direction → Visual Concept → Build → Review / QA`.

- Исследование и прототипирование могут итеративно уточняться; **до дорогого художественного производства должна быть утверждена достаточная логическая основа**.
- Маршрут Figma/HTML/Hybrid выбирают по [Production Routing](production-routing.md), а не по одному названию «лендинг».
- Mobile-first, полнота решения до утверждения, системная целостность, источник истины и проверки качества применимы в любом режиме.
- При наличии **действительно принятого актуального прототипа** не создавай его повторно. Укажи источник, ограничения и изменённую область.
- В продукте с несколькими страницами «вся система» означает IA/шаблоны/маршруты; **не требуется нарисовать весь сайт** до начала поэтапной реализации.

## Формат результата классификации: 5 строк

- Тип и смешанные признаки проекта.
- Количество/характер уникальных экранов, шаблонов, ключевых маршрутов.
- Режим глубины + 1–2 основания.
- Минимально достаточный прототип и что нужно утвердить до Art Direction.
- Риски и условия изменения режима.

Не заводить обязательную анкету или отдельный объёмный отчёт: сохранить в Start/Project Contract.
