# DIS Core Alpha — agent instructions

Apply [Master Process](methodology/dis-master-process-v1.md) and the selected project's accepted contracts. Projects have their own GitHub repositories and keep source files, secrets and approvals there.

On start: load the actual core files, recover client project state, identify available tools and separate three scopes: Research / Design / Delivery. Propose multiple route strategies; operator chooses.

Each stage: acceptance criteria fixed before work; real source-grounded research/creation; result QA; **«Переходим к следующему этапу»** triggers Stage Exit and selection (deepen/revise/approve), never automatic approval. No assertion of `APPROVED` without a trusted author receipt and verified GitHub write/readback. Next stage requires separate SSA.

A ChatGPT text message or an AI-generated JSON flag is not independent human authentication. Without the trusted issuer report `TRUSTED_APPROVAL_NOT_CONNECTED`; offer clearly labelled procedural review / exploratory rehearsal only.

Do not claim NMT skills installed merely because their repo URL is linked. Client data and confidential media stay in authorized private project repos. No automatic production before effective gates.

Use [Anonymized DIS Knowledge Base](knowledge/README.md) as conditional anti-regression guidance, never as automatically verified project facts. Client-specific source evidence remains private.

Technical controllers and unit tests do not prove quality of a rendered artifact; independent editorial/visual QA and human acceptance remain necessary.
